# vkt-header

[English](../README.md) | [中文](README_zh.md) | [Español](README_es.md) | [Deutsch](README_de.md) | 日本語 | [Français](README_fr.md)

Chromiumブラウザ向けのグローバルHTTPリクエストヘッダー修飾子です。ルールは**ドメインのみ**で一致判定され（大文字小文字を区別せず、パスは無視）、**すべてのタブ**に適用されます — タブ分離やタブごとの状態管理はありません。

> Chromium · Manifest V3 · Session Rules · ドメインマッチング · グローバル

---

## vkt-headerの特長

ほとんどのヘッダー修飾子はグローバルにヘッダーを変更するか、煩雑なタブごとの状態管理が必要です。vkt-headerはシンプルに保っています：リクエストURLの**ドメイン**でルールが一致判定され、有効化された瞬間からすべてのタブ、すべての場所で適用されます。

| 特長 | 詳細 |
|-----------|--------|
| 🌐 **ドメインマッチング** | ルールはドメインのみで一致判定、大文字小文字を区別しません。パスは無視されます。 |
| 🔗 **任意のタブ** | ルールはすべてのタブで適用されます — 特定のタブにバインドされることはありません。 |
| 🌍 **グローバルルール** | Match URLを空にすると、ルールは**すべてのリクエスト**に適用されます。 |
| 🧹 **自動再適用** | Session rulesはブラウザ再起動時に消滅しますが、vkt-headerはブラウザ起動時にすべての有効なルールを自動的に再適用します。 |
| ⚡ **インライン編集** | サイドパネルでヘッダーを直接追加/編集。別途エディタは不要。 |
| 🎯 **プリセット** | ワンクリックプリセット：iPhone、Android、iPad、Googlebot、Referer、X-Forwarded-For。 |

## コア機能：ドメインマッチング

各ルールには**Match URL**フィールドがありますが、使用されるのは**ドメイン**部分のみです：

- 一致判定は**大文字小文字を区別しません**（`EXAMPLE.COM` = `example.com`）
- パスは無視されます（`https://example.com/api`は`example.com`とまったく同じに動作）
- 先頭の`www.`はオプションです — `https://www.cnblogs.com/`と`https://cnblogs.com/`は同じルールに一致
- 他のサブドメイン（`pic.cnblogs.com`、`blog.cnblogs.com`、…）には一致**しません**
- オプションの**サブドメインを含む**トグル：有効にすると、`example.com`がすべてのサブドメイン（`pic.example.com`、`api.example.com`、…）にも一致
- ルールは**すべてのタブ**で、ドメインが一致するすべてのリクエストに適用
- **Match URLが空** = ルールは**すべてのリクエスト**に適用

| 入力内容 | 有効なドメイン | 適用先 |
|---|---|---|
| `example.com` | example.com | example.comとwww.example.com、すべてのパス |
| `HTTPS://EXAMPLE.COM/api` | example.com | 同上 — パスは無視 |
| `https://www.cnblogs.com/` | cnblogs.com | cnblogs.comとwww.cnblogs.com |
| `pic.cnblogs.com` | pic.cnblogs.com | pic.cnblogs.comとwww.pic.cnblogs.comのみ |
| *（空）* | — | **すべてのリクエスト** |

サイドパネルのスイッチでルールを有効化します。上部のマスタースイッチですべてのルールを一括停止・再開できます。

## 機能一覧

| 機能 | 説明 |
|---------|-------------|
| **ヘッダーの設定／追加／削除** | 任意のヘッダーを上書き、追加（Cookie、X-Forwarded-For…）、または削除 |
| **リクエスト＆レスポンスヘッダー** | ルールごとにリクエストヘッダーとレスポンスヘッダーを個別に修飾 |
| **インラインエディタ** | サイドパネルでヘッダーを直接編集 — ポップアップ/パネル切り替え不要 |
| **ルールシステム** | 複数のヘッダー設定をルールとして保存 |
| **ドメインバインド** | ルールをドメインにバインド（大文字小文字区別なし、パス無視） |
| **サブドメインを含む** | オプショントグル：すべてのサブドメイン（`*.example.com`）に一致 |
| **メソッドフィルター** | ルールを1つのHTTPメソッド（GET、POST、…）に制限、またはオープンに設定 |
| **グローバルルール** | 空のMatch URL → すべてのリクエストに適用 |
| **URLタグ** | 現在のページのドメインをクリックしてMatch URLを自動入力 |
| **ルールごとのスイッチ** | 各ルールを個別に有効/無効化。マスタースイッチで一括停止 |
| **プリセット** | 一般的なヘッダーをクイック追加：モバイルUA、ボットUA、Referer、XFF |
| **任意のタブ** | ルールはグローバル — タブ分離なし、タブごとのトグルなし |
| **Session rules** | `declarativeNetRequest`セッションルール — 再起動時に自動クリア、ブラウザ起動時に自動再適用 |
| **インポート／エクスポート** | すべてのルールのJSONバックアップ＆復元 *（Premium）* |

## インストール

安全性のため、公式ブラウザ拡張機能ストアを通じてのみvkt-headerをインストールしてください：

1. **Chrome Web Store**または**Microsoft Edge Add-ons**を開きます
2. 検索：`vkt-header`
3. **「Chromeに追加」** / **「Edgeに追加」**をクリックします
4. ツールバーの🔧 vkt-headerアイコンをクリックしてサイドパネルを開きます

> ⚠️ サードパーティWebサイトからのインストールは避けてください。非承認版はデータセキュリティを損なう可能性があります。

## プライバシー

vkt-headerはプライバシー・バイ・デザインの原則に従っています：

- ✅ すべてのルールは`chrome.storage.local`に保存 — **データがサーバーにアップロードされることはありません**
- ✅ Session rulesはブラウザ再起動時に自動クリアされ、ブラウザ起動時に自動再適用されます
- ✅ アナリティクス、トラッキング、Cookieなし
- ✅ 一部のヘッダー（Host、Origin）はブラウザ保護されており、変更できません
- ✅ 開発およびデバッグ目的のみ

### 権限

| 権限 | 理由 |
|------------|--------|
| `storage` | ヘッダールールと設定をローカルに保存 |
| `activeTab` | 現在のタブにアクセス（サイドパネルでURLを読み取るため） |
| `sidePanel` | サイドパネルで拡張機能UIを表示 |
| `declarativeNetRequestWithHostAccess` | HTTPリクエストヘッダーを修飾 |
| `tabs` | ドメインタグ機能用にアクティブタブのURLを読み取り |

- [プライバシーポリシー全文](https://annmax1983.github.io/vkt-header/privacy-policy.html)

## よくある質問

1. **ルールを有効にしてもヘッダーが適用されない？**
   ページを再読み込みしてみてください。DNR Session rulesは新しいリクエストに適用され、すでに読み込まれたリソースには適用されません。

2. **ブラウザ再起動後にルールが消える？**
   Session rulesは仕様により再起動時にクリアされます。vkt-headerはブラウザ起動時にすべての有効なルールを自動的に再適用します。

3. **一部のヘッダーが変更できない？**
   ブラウザ保護ヘッダー（Host、Originなど）は拡張機能で変更できません。これはブラウザのセキュリティ制限であり、バグではありません。

4. **ルールを別のデバイスに移行するには？**
   設定 → エクスポートを開いてJSONバックアップをダウンロードし、別のデバイスでインポートしてください。

5. **ホームページ／最初のナビゲーションでヘッダーが表示されない？**
   DNRルールはブラウザキャッシュから配信されたリクエストには適用されません。ルールを有効にした後、ページをハードリフレッシュ（Ctrl+Shift+R）するか再度開いてください — ナビゲーションリクエストにヘッダーが付与されます。キャッシュされたサブリソースも同様です。

6. **ブラウザ起動直後にヘッダーが欠落する？**
   Service Workerは遅延起動するため、vkt-headerがSession rulesを再適用する前に最初のリクエストが発火する場合があります。再試行または再読み込みしてください — それ以降のすべてのナビゲーションにヘッダーが付与されます。これはブラウザ起動直後の最初の瞬間にのみ影響し、通常のブラウズには影響しません。
